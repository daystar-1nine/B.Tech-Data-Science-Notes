**Q1. Differentiate between Data, Database, and DBMS.**

| Feature | Data | Database | DBMS |
| :--- | :--- | :--- | :--- |
| **Meaning** | Raw, unprocessed facts | Organized collection of related data | Software to manage the database |

| **Usefulness** | Meaningless alone | Meaningful when queried | Makes database useful and accessible |

**Q2. List and briefly explain any three characteristics of a database.**

1. **Data Integrity:** The DBMS enforces rules (constraints) to ensure that all data stored is accurate, valid, and consistent. For example, a student's age cannot be stored as a negative number.

2. **Data Security:** The DBMS controls who can access which data using authentication (login) and authorization (permissions/privileges). This prevents unauthorized access or modification.

3. **Reduced Data Redundancy:** In traditional file systems, the same data (e.g., a student's address) might be stored in multiple files, leading to inconsistency. A DBMS minimizes this by centralizing data and using normalization.

**Q3. Explain the three levels of Data Abstraction.**

The DBMS provides three levels of abstraction to hide complexity from users:

1. **Physical Level (Internal):** The lowest level. Describes *how* data is physically stored on the disk — file formats, indexing, data blocks, and storage structures. Hidden from all users.

2. **Logical Level (Conceptual):** The middle level. Describes *what* data is stored and the relationships between them — i.e., the table schemas and constraints. Used by DBAs and programmers.

3. **View Level (External):** The highest level. Describes only a *part* of the database as seen by a specific user or application. Different users may see different views. Provides simplicity and security.

```
View Level    (What user sees — partial view)
Logical Level (What data exists — full schema)
Physical Level(How data is stored — on disk)
```

**Q4. Differentiate between Logical and Physical Data Independence.**

| Feature | Logical Data Independence | Physical Data Independence |
| :--- | :--- | :--- |
| **Definition** | Ability to change the logical schema without affecting the view level | Ability to change the physical schema without affecting the logical level |
| **Level of Change** | Conceptual/Logical schema changes | Physical/Internal schema changes |
| **Example** | Adding a new column to a table without affecting old application code | Changing from sequential file storage to B-tree indexing |
| **Difficulty** | Harder to achieve | Easier to achieve |

**Q5. Explain 1-tier, 2-tier, and 3-tier architecture in brief.**

1. **1-Tier Architecture:** The client, application logic, and database all reside on one machine. Used for personal/local applications. Simple but not scalable.
   *Example: MS Access on a local PC.*

2. **2-Tier Architecture:** The client (with application logic) communicates directly with a database server over a network. Better than 1-tier for small teams.
   *Example: A desktop inventory app connecting to a remote MySQL server.*

3. **3-Tier Architecture:** Three distinct layers — (a) **Presentation Tier** (client UI), (b) **Application/Logic Tier** (business rules, middle-ware), and (c) **Database Tier** (data storage). Most scalable and secure; used in modern web applications.
   *Example: A web browser → Web server (Apache) → Oracle DB.*

**Q6. What are the tasks/functions offered by a DBMS?**

1. **Data Definition:** The DBMS allows users to define the structure (schema) of the database — creating tables, setting data types, and defining constraints using DDL (Data Definition Language).

2. **Data Updation:** The DBMS provides DML (Data Manipulation Language) commands like `INSERT`, `UPDATE`, and `DELETE` to add, modify, or remove data in the database.

3. **Data Retrieval:** Users can query the database to fetch specific data using the `SELECT` statement. The Query Processor optimizes and executes these queries.

4. **User Administration:** The DBA can create user accounts, grant or revoke privileges, and control access to specific tables or operations — ensuring data security.

---

**Q7. Explain any three components of the Storage Manager.**

1. **Authorization and Integrity Manager:** Checks that a user has the required permissions before executing a data access operation. Also enforces integrity constraints (e.g., primary key, NOT NULL).

2. **Transaction Manager:** Ensures that database transactions execute reliably. It manages the ACID (Atomicity, Consistency, Isolation, Durability) properties, handles failure recovery, and maintains the database in a consistent state.

3. **Buffer Manager:** Manages the transfer of data between disk storage and main memory (RAM). It fetches data pages into a buffer pool in RAM and decides which pages to write back to disk, minimizing costly disk I/O operations.

---

**Q8. Explain DDL interpreter, DML compiler, and Query evaluation engine in brief.**

1. **DDL Interpreter:** Interprets Data Definition Language (DDL) statements like `CREATE TABLE` and `DROP TABLE`. It records the definitions (metadata) in the **data dictionary**.

2. **DML Compiler:** Translates DML queries (like `SELECT`, `UPDATE`) written in high-level SQL into low-level query plans (procedural instructions) that the query evaluation engine can execute.

3. **Query Evaluation Engine:** Executes the low-level query plan generated by the DML compiler. It coordinates with the Storage Manager to physically access the data on disk and return the result to the user.

---

**Q9. List any three responsibilities of a DBA.**

1. **Schema Definition:** The DBA writes DDL statements to create the original database schema (tables, views, indexes, constraints) and loads the initial data.

2. **Granting User Access:** The DBA creates user accounts and uses `GRANT` and `REVOKE` commands to control which users have access to which parts of the database, ensuring security.

3. **Routine Maintenance & Monitoring:** The DBA monitors system performance, performs periodic backups to prevent data loss, plans recovery procedures for failures, and tunes the database configuration for optimal performance.

**Q11. Explain the need for a database (any three points).**

1. **Eliminating Data Redundancy and Inconsistency:** In file systems, the same data (e.g., a customer's phone number) is stored in multiple files, leading to inconsistency when one is updated but others are not. A DBMS stores data centrally, eliminating redundancy.

2. **Difficulty in Accessing Data:** Retrieving data from flat files requires writing custom programs for every query. A DBMS provides a powerful query language (SQL) that allows easy, ad-hoc retrieval of data without programming.

3. **Data Security and Integrity:** File systems have limited access control. A DBMS provides fine-grained security using user accounts, privileges, and integrity constraints (like NOT NULL, FOREIGN KEY), ensuring only valid and authorized data operations occur.

**Q12. Write short notes on Specialized Users.**

**Specialized Users** are sophisticated users who write specialized database applications that don't fit the traditional data processing framework. They work with advanced database features and technologies such as:
- **Knowledge Base Systems:** Systems that store rules and facts (AI/Expert systems).
- **CAD Systems:** Computer-Aided Design systems that store complex geometric and engineering data.
- **Geographic Information Systems (GIS):** Applications that store and query spatial/map data.
These users often interact with specialized DBMS types (e.g., Graph DBMS, Spatial DBMS) that go beyond the standard relational model.

**Q13. Differentiate File System and Database approach (any 3 points).**

| Feature | File System | Database System |
| :--- | :--- | :--- |
| **Data Redundancy** | High — same data stored in multiple files, leading to inconsistency | Low — data stored centrally, redundancy minimized via normalization |
| **Data Access** | Requires custom programs to access/query data; no standard query language | Standard SQL provides easy, powerful, and flexible data retrieval |
| **Data Security** | Limited security; access is mainly at the file/folder level via OS | Fine-grained security with user accounts, roles, and privileges per table/column |
| **Data Integrity** | No built-in constraints; integrity is managed manually in programs | DBMS enforces constraints (PK, FK, NOT NULL) automatically |
| **Concurrency** | Very limited support; simultaneous file access can corrupt data | Built-in concurrency control ensures safe simultaneous multi-user access |
