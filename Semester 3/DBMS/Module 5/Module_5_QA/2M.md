# 2-Mark Questions & Answers — DBMS Module 5: Query Optimization & Concurrency Control

---

### Q1. What is Query Optimization and what is its primary objective?

**Query Optimization** is the DBMS process of analyzing an incoming declarative SQL query, formulating multiple logically equivalent execution plans, and selecting the physical plan with the lowest estimated execution cost.
* **Primary Objective:** Minimize total physical resource consumption, specifically **Disk Block I/O transfers**, disk head seeks, and CPU cycles.

---

### Q2. Define a Database Transaction and state the ACID properties.

A **Transaction** is a single logical unit of database work consisting of one or more database access operations (`Read` and `Write`).
* **ACID Properties:**
  1. **Atomicity:** All-or-nothing execution.
  2. **Consistency:** Transforms the database between valid states upholding all constraints.
  3. **Isolation:** Concurrent transactions execute without mutual interference.
  4. **Durability:** Committed updates survive system crashes and power failures.

---

### Q3. What is Conflict Serializability? State the condition for two operations to conflict.

A concurrent schedule is **Conflict Serializable** if it is conflict equivalent to some serial schedule (it can be transformed into a serial schedule by repeatedly swapping non-conflicting adjacent operations).
* **Conflict Condition:** Two operations conflict if and only if they belong to different transactions, access the exact same data item, and at least one operation is a **Write**.

---

### Q4. Differentiate between Shared (S) and Exclusive (X) locks.

* **Shared Lock (`S`):** Granted for read-only operations (`Read(Q)`). Multiple transactions can concurrently hold shared locks on the same data item.
* **Exclusive Lock (`X`):** Granted for write operations (`Write(Q)`). Grants sole read/write access to one transaction; blocks all other transactions from holding any lock on that item.

---

### Q5. What is the Phantom Phenomenon?

The **Phantom Phenomenon** occurs when a concurrent transaction inserts or deletes records satisfying a search predicate while another transaction is performing repeated range queries over that same predicate, causing newly created "phantom" records to appear unexpectedly in subsequent reads.

---

### Q6. State the Thomas Write Rule in Timestamp Ordering.

The **Thomas Write Rule** is a concurrency optimization: if a transaction `T_i` attempts to execute `Write(Q)` but its timestamp is smaller than the item's write timestamp (`TS(T_i) < W-TS(Q)`), the DBMS **silently ignores and discards `T_i`'s obsolete write** rather than aborting `T_i`, thereby improving concurrency while preserving view serializability.

---

### Q7. State the two fundamental rules of the Write-Ahead Logging (WAL) protocol.

1. **Undo Rule (WAL-1):** Before any dirty database buffer block is written to disk, the log record containing the item's old value (before-image) must be flushed to stable log storage.
2. **Redo Rule (WAL-2):** Before a transaction can declare itself committed, all of its log records—including `<T, commit>`—must be flushed to stable storage.

---

### Q8. What is a Checkpoint in database recovery and why is it used?

A **Checkpoint** is a periodic synchronization point where the DBMS flushes all dirty memory buffers and active log records to disk and records `<CHECKPOINT {active_transactions}>` in the log.
* **Purpose:** It bounds crash recovery time by ensuring the recovery manager never needs to scan log records prior to the most recent checkpoint.
