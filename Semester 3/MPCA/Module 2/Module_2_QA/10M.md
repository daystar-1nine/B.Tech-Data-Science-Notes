### Q1. Explain hardwired and microprogrammed control units in detail with block diagrams, and compare their advantages/disadvantages.

#### 1. Hardwired Control Unit Architecture

```
                       +-------------------------------+
                       | INSTRUCTION REGISTER (IR)     |
                       +-------------------------------+
                                       |
                                       v
+------------------+         +-------------------+         +-----------------------+
| SYSTEM CLOCK     | ------->| OPCODE DECODER    | <-------| SEQUENCE COUNTER      |
+------------------+         +-------------------+         | & CONDITION FLAGS     |
                                       |                   +-----------------------+
                                       v
                            +----------------------+
                            | COMBINATIONAL LOGIC  |
                            | MATRIX (Gates)       |
                            +----------------------+
                                       |
                                       v
                            Control Signals (Read/Write/ALU)
```

#### 2. Microprogrammed Control Unit Architecture

```
+---------------------+     +-----------------------+     +----------------------+
| CONTROL ADDRESS     | --> | CONTROL MEMORY (ROM)  | --> | CONTROL DATA REGISTER|
| REGISTER (CAR)      |     | (Microcode Storage)   |     | (CDR / Microinst)    |
+---------------------+     +-----------------------+     +----------------------+
           ^                                                         |
           |                  +---------------------+                v
           +----------------- | SEQUENCER LOGIC     | <---- Control Signals to Hardware
                              +---------------------+
```

#### 3. Comprehensive Comparison Table

| Feature | Hardwired Control Unit | Microprogrammed Control Unit |
| :--- | :--- | :--- |
| **Logic Implementation** | Fixed combinational logic gates & flip-flops. | Microcode software stored in Control Memory ROM. |
| **Execution Speed** | Extremely fast (limited only by hardware gate delay). | Slower (dependent on Control ROM fetch cycle time). |
| **Flexibility** | Rigid. Modifications require hardware redesign. | Highly flexible. Upgraded by updating Control ROM microcode. |
| **Instruction Set Type** | Best suited for RISC architectures. | Best suited for complex CISC architectures. |
| **Cost & Complexity** | High cost and design complexity for large ISAs. | Systematic design, lower cost for complex ISAs. |
| **Debugging & Maintenance**| Difficult to debug and maintain. | Easier to debug and maintain. |

### Q2. Explain instruction pipelining in detail. Discuss structural, data, and control hazards with examples and methods to resolve each (forwarding, stalling, branch prediction).

#### 1. 5-Stage RISC Instruction Pipeline

```
Stage 1: IF  (Instruction Fetch)   -> Read instruction from I-Cache.
Stage 2: ID  (Instruction Decode)  -> Read registers & decode instruction.
Stage 3: EX  (Execution / ALU)     -> Execute ALU operation or calculate memory address.
Stage 4: MEM (Memory Access)       -> Read/Write data from D-Cache.
Stage 5: WB  (Write Back)          -> Write result back into destination register.
```

#### 2. Pipeline Hazards & Resolution Strategies

1. **Structural Hazards (Resource Contention):**
   - *Example:* A single-port memory attempting simultaneous instruction fetch (`IF`) and data memory read (`MEM`).
   - *Resolution:* Implement separate Instruction and Data Caches (Harvard Architecture model).

2. **Data Hazards (Data Dependencies):**
   - *Example (RAW Hazard):*
     ```assembly
     ADD R1, R2, R3   ; R1 written in WB stage
     SUB R4, R1, R5   ; R1 read in ID stage (Hazard!)
     ```
   - *Resolution Methods:*
     - **Data Forwarding (Bypassing):** Connect the ALU output of `EX` stage directly back to `EX` stage input via a multiplexer, eliminating wait cycles.
     - **Pipeline Stalling (NAPs / Bubbles):** Insert hardware stall cycles until data is written back.

3. **Control Hazards (Branch Dependencies):**
   - *Example:* Conditional branch instruction `BEQ R1, R2, Target` alters sequential instruction fetching.
   - *Resolution Methods:*
     - **Static/Dynamic Branch Prediction:** Predict whether branch is taken or not taken (Branch History Table).
     - **Branch Target Buffer (BTB):** Cache branch target addresses for instant fetching.

### Q3. Explain the basic instruction cycle with interrupt processing in detail, including the fetch-decode-execute cycle and interrupt handling mechanism.

```
                      +-------------------+
                      |   FETCH STAGE     |
                      |   MAR <- PC       |
                      |   MDR <- M[MAR]   |
                      |   IR  <- MDR      |
                      |   PC  <- PC + 1   |
                      +-------------------+
                                |
                                v
                      +-------------------+
                      |   DECODE STAGE    |
                      |   Decode Opcode   |
                      |   Fetch Operands  |
                      +-------------------+
                                |
                                v
                      +-------------------+
                      |   EXECUTE STAGE   |
                      |   ALU Compute     |
                      |   Write Result    |
                      +-------------------+
                                |
                                v
                      +-------------------+
                      | INTERRUPT CHECK?  |
                      +-------------------+
                         /                                YES  /               \ NO
                       v                 v
            +--------------------+    Next Cycle (Fetch)
            | Push PC & FLAGS    |
            | Load ISR Address   |
            +--------------------+
```

#### Detailed Phase Breakdown
1. **Fetch:** CPU transfers `PC` to `MAR`, issues memory read signal, loads fetched byte into `IR`, and increments `PC`.
2. **Decode:** Opcode is decoded; operand addresses are calculated.
3. **Execute:** ALU executes mathematical or logic operation.
4. **Interrupt Servicing Mechanism:**
   - At the conclusion of execution, CPU checks interrupt line status.
   - If an interrupt request is active:
     1. Current `FLAGS`, `CS`, and `IP` are pushed onto the Stack.
     2. Interrupt Enable (`IF`) and Trap (`TF`) flags are cleared.
     3. Interrupt vector address is loaded into `CS:IP`.
     4. Control transfers to ISR; ends with `IRET` restoring original context.

### Q4. Describe microinstruction sequencing and execution techniques (in microprogrammed control) along with a suitable example of microinstruction format.

#### 1. Microinstruction Format Structure

```
+-------------------+--------------------+--------------------+--------------------+
| CONTROL FIELD     | CONDITION FIELD    | BRANCH FIELD       | ADDRESS FIELD      |
| (Control Signals) | (Status Flags Test)| (Jump Condition)   | (Next Micro-Addr)  |
| (16-32 bits)      | (2-4 bits)         | (2-3 bits)         | (8-12 bits)        |
+-------------------+--------------------+--------------------+--------------------+
```

#### 2. Microinstruction Sequencing Techniques

1. **Two-Address Fields:**
   - Microinstruction contains two explicit address fields: Next address if condition is TRUE, and Next address if condition is FALSE.
2. **Single-Address Field with Increment:**
   - Microinstruction contains one address field used for branching; if no branch occurs, `CAR` is automatically incremented (`CAR = CAR + 1`).
3. **Variable Format / Opcode Mapping:**
   - Opcode bytes from machine instruction are mapped via a PLA/ROM lookup table directly into the starting microinstruction address in Control ROM.

### Q5. Explain Flynn's classification of computer architectures in detail with block diagrams and real-world examples for each category.

```
1. SISD Architecture                  2. SIMD Architecture
   +----+     +----+     +------+        +----+     +-----+ -> [PE1] -> [Mem1]
   | CU | --> | PE | --> | Mem  |        | CU | --> | Bus | -> [PE2] -> [Mem2]
   +----+     +----+     +------+        +----+     +-----+ -> [PE3] -> [Mem3]

3. MISD Architecture                  4. MIMD Architecture
   +-----+     +-----+                   +-----+     +-----+     +------+
   | CU1 | --> | PE1 | -\                | CU1 | --> | PE1 | --> | Mem1 |
   +-----+     +-----+   \               +-----+     +-----+     +------+
                          +-> [Shared]
   +-----+     +-----+   /               +-----+     +-----+     +------+
   | CU2 | --> | PE2 | -/                | CU2 | --> | PE2 | --> | Mem2 |
   +-----+     +-----+                   +-----+     +-----+     +------+
```

1. **SISD (Single Instruction, Single Data):** Standard uniprocessor architecture executing sequential instructions on a single scalar data stream.
   - *Example:* Intel 8086, early Pentium processors.
2. **SIMD (Single Instruction, Multiple Data):** Single control unit dispatches one instruction to multiple Processing Elements (PEs) operating concurrently on distinct data vector streams.
   - *Example:* Nvidia GPUs (CUDA cores), Intel AVX-512 extensions.
3. **MISD (Multiple Instruction, Single Data):** Multiple autonomous control units execute distinct instructions on a single shared data stream.
   - *Example:* Spacecraft redundant flight computers.
4. **MIMD (Multiple Instruction, Multiple Data):** Independent processors execute autonomous instruction streams on independent data streams.
   - *Example:* Multi-core CPUs (Intel Core i9, AMD EPYC), Supercomputer clusters.
